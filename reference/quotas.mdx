---
title: "Limits and Credits"
description: "Realtime session limits, video concurrency, and credit behavior."
---

Limits vary by plan. Use `GET /v1/billing/quota` to read the limits currently
applied to your account.

## Realtime sessions

Realtime plans set the maximum number of concurrent sessions and the maximum
length of each session. Exceeding the concurrency cap returns
`429 quota_exceeded` with `error.code: "concurrent_sessions"`.

| Limit | Default |
| --- | --- |
| Idle timeout | 30 seconds without input audio |
| Metadata size | 8 KB |
| Create rate limit | 10 requests per minute per key |
| Idempotency window | 24 hours |

The idempotency window applies to `Idempotency-Key` on supported `POST`
endpoints. If you retry the same request with the same key during this window,
Protoface returns the first result instead of creating another session or
video.

If you send `max_duration_seconds`, Protoface applies the lower of your request
and your plan limit.

## Realtime credits

Usage is rounded up to the nearest minute. One credit equals one rounded-up
session minute. If the account has no usable credits, session creation returns
`402 quota_exceeded` with
`error.code: "insufficient_credit_balance"`.

Free monthly credits do not roll over. Purchased credits roll over without
expiry.

## Video generation

Submitting a run reserves the `maximum_reserved_credits` returned in its
estimate. A completed run charges that reservation. A failed run releases it.

Each plan also limits concurrent video runs. If the account is at its limit,
the API returns `429 quota_exceeded`. Wait for an active run to finish before
submitting another one.

Canceling a queued run releases its reservation. Canceling after work starts
charges the reserved amount.

## Metadata keys

`metadata` is customer-owned JSON. Keys beginning with `_avatar.` are managed by
Protoface and are reserved for support-directed use.
