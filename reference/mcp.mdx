`protoface-mcp` gives your coding agent 17 typed tools for media
generation: discover models, submit runs, poll status, download outputs,
manage assets, and check spend. Install once, then ask for videos.

This covers media generation only. Realtime avatar sessions, custom
avatars, and website embeds stay on the API — start with
[Quickstart](/quickstart) for those.

## Prerequisites

- [uv](https://docs.astral.sh/uv/) installed (`uvx` runs the server).
- A Protoface API key from the [dashboard](https://app.protoface.com).
  See [Authentication](/guides/authentication).

## Setup

Add one block, then restart your agent. Replace `sk_live_...` with your key.

**Codex** — `~/.codex/config.toml` (with `PROTOFACE_API_KEY` exported in
your shell):

```toml
[mcp_servers.protoface]
command = "uvx"
args = ["protoface-mcp"]
env_vars = ["PROTOFACE_API_KEY"]
```

**Claude Code** — `.mcp.json` in your project root:

```json
{
  "mcpServers": {
    "protoface": {
      "command": "uvx",
      "args": ["protoface-mcp"],
      "env": { "PROTOFACE_API_KEY": "sk_live_..." }
    }
  }
}
```

**Cursor** — `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "protoface": {
      "command": "uvx",
      "args": ["protoface-mcp"],
      "env": { "PROTOFACE_API_KEY": "sk_live_..." }
    }
  }
}
```

Verify with:

```text
Using Protoface, list the available models and my credit balance.
```

## Give your agent the skill

The MCP server provides the tools; the skill teaches the workflow. Save
this as `SKILL.md` under a `protoface-media` skills folder:

- Codex: `~/.agents/skills/protoface-media/SKILL.md`
- Claude Code: `~/.claude/skills/protoface-media/SKILL.md` (personal) or
  `.claude/skills/protoface-media/SKILL.md` (project)

```markdown
---
name: protoface-media
description: Generate images, video, and audio with Protoface models. Use when the user wants to create media, check generation status, download results, or manage generation assets and spend.
---

# Protoface media generation

Requires the `protoface` MCP server (tools below) and a `PROTOFACE_API_KEY`.
If tools are missing, tell the user to install `protoface-mcp`
(see https://docs.protoface.com/reference/mcp) and retry.

## Generate media (the core loop)

Never guess a payload shape. Every model has its own input contract:

1. **Discover**: `list_models` → pick a model → `get_model`. Read its
   `request_schemas` (per-operation JSON schemas), `operations`, modalities,
   and `pricing`. If the model has multiple operations, confirm which one
   the user wants.
2. **Inputs first**: if the payload needs source files (images, audio),
   `upload_asset` each local file and reference the returned asset ids.
3. **Check spend**: `get_quota_limits` before submitting anything large.
   Refuse to spend the user's credits blind — state the expected cost.
4. **Submit**: `submit_run` with the schema-shaped payload. Pass an
   `idempotency_key` (any opaque string) whenever retrying, so a duplicate
   submit returns the original run instead of double-spending.
5. **Poll**: `get_run_status` until terminal. It is cheap — poll it, not
   `get_run`. Back off (seconds, not milliseconds); `list_run_events`
   with `after` shows progress detail for long runs.
6. **Collect**: `get_run` → `outputs[]`. Each entry has `type`:
   `asset` (downloadable `file.url` + `asset_id`), `text`, or `data`.
   Use `download_asset` when the user wants the file on disk.

## Status vocabulary

In-flight: `queued` (`queue_position` tells where), `running` (`progress`
is 0–100). Terminal: `completed`, `failed` (read `error.code`/`message`),
`canceled`. Terminal states are final — never re-poll them.

## Errors

Tool failures lead with a stable wire code in brackets (e.g.
`[quota.exceeded]`). Switch on the code, not the message. On auth errors,
ask the user to check `PROTOFACE_API_KEY`; on quota errors, report
`get_quota_limits` and stop spending.

## Out of scope

This skill covers media generation only. Realtime avatar sessions, custom
avatars, and website embeds are separate Protoface surfaces — say so and
point at https://docs.protoface.com instead of improvising.
```

## Tools

| Group | Tools |
| --- | --- |
| Runs | `submit_run`, `get_run_status`, `get_run`, `cancel_run`, `list_runs`, `list_run_events` |
| Models | `list_models`, `get_model` (input contracts live here) |
| Assets | `upload_asset`, `list_assets`, `get_asset`, `download_asset`, `delete_asset` |
| Spend and health | `get_usage_summary`, `list_billing_plans`, `get_quota_limits`, `get_status` |

Run statuses: `queued` → `running` → `completed` / `failed` / `canceled`.
Submit reserves credits up front; if a run starts before your cancel
lands, the started work is charged. Pass an `idempotency_key` to
`submit_run` when retrying so a duplicate never double-spends. Full
endpoint details live under [API Reference](/api-reference/index).

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `PROTOFACE_API_KEY is not set` | Export the key (Codex) or check the `env` block (Claude Code, Cursor), then restart the agent. |
| `[api_key.unknown]` | Wrong or mistyped key. Recreate it in the [dashboard](https://app.protoface.com) and check [Authentication](/guides/authentication). |
| `[model.not_found]` | Call `list_models` — model ids change as the catalog grows. |
| Quota errors | Call `get_quota_limits`, then top up in the [dashboard](https://app.protoface.com). |
| Run stuck in `queued` | Check `queue_position` and keep polling — don't resubmit. |
| Tool failures with a `[code]` | Switch on the code, not the message. See [Errors](/reference/errors). |
